# Тех задание проекта "Coffee Bakery"

## Frontend
1. **React + Vite (или Next.js)**
Для учебного проекта лучше начать с Next.js, а не чистого React+Vite, по нескольким причинам:
    - у тебя есть страница товара — Next.js даёт готовый файловый роутинг (`/product/[id]`) без установки react-router;
    - админка на `/admin` — тоже просто отдельная папка в роутере;
    - в будущем нужна авторизация (email/телефон/Google/Facebook) — для Next.js есть готовое решение NextAuth.js (см. ниже), которое сильно упрощает эту часть;
    - API-запросы (создание заявки, работа с товарами) можно писать прямо внутри Next.js как API-роуты — не нужен отдельный backend-проект для старта.

Если хочется именно "чистого" React ради обучения самому React без фреймворка — тогда React + Vite + React Router, но тогда backend придётся делать отдельным Express-проектом.

2. **TypeScript**
Не обязательно, но для учебного проекта это отличная практика: у тебя уже есть чёткая структура товара (id, name, price, stock_quantity и т.д.) — типизация не даст ошибиться в полях при работе с корзиной и заявками.

3. **Tailwind CSS**
Много кастомной вёрстки (табы категорий, слайдер отзывов, виджет корзины со счётчиками) — Tailwind ускоряет вёрстку и не заставляет писать отдельные CSS-файлы под каждый компонент.

4. **Zustand (управление состоянием корзины)**
Корзина используется в нескольких местах: счётчик в хедере, виджет корзины, кнопки +/- на карточках товара. Всё это должно синхронизироваться. Zustand — простая и лёгкая альтернатива Redux, без лишнего boilerplate, отлично подходит для такой задачи. Можно также сохранять корзину в `localStorage`, чтобы она не терялась при обновлении страницы.

5. **Font Awesome**
Для иконок интерфейса (корзина, соцсети, категории, стрелки слайдера, статусы заказа и т.д.) — большая готовая библиотека иконок, не нужно рисовать/подбирать SVG самому. Для Next.js проще всего подключить через официальный пакет `@fortawesome/react-fontawesome` вместе с нужными наборами иконок (`@fortawesome/free-solid-svg-icons`, `@fortawesome/free-brands-svg-icons` и т.д.) — иконки рендерятся как React-компоненты, что вписывается в общий подход проекта, без подключения через CDN <link>.

6. **Библиотека для слайдера** (например, Swiper или Embla Carousel)
Для блока отзывов со слайдером — не нужно писать логику свайпа самому.

## Backend

6. **Next.js API Routes** (или отдельный Express, если хочется разделения)
Для обработки заявок (создание заказа), CRUD товаров в админке. Если проект вырастет — можно вынести в отдельный сервис на Node.js + Express, но для учебных целей API Routes в Next.js вполне достаточно и проще в деплое.

7. **PostgreSQL + Prisma ORM**
У тебя реляционные данные: товары, категории, заказы, товары в заказе. PostgreSQL — надёжный выбор, Prisma даёт удобную типизированную работу с БД и автогенерацию схемы прямо из `menu.json` (можно один раз написать скрипт-сидер, который загрузит твой JSON в базу).

Альтернатива — MongoDB, если не хочется связей между таблицами и удобнее хранить товары как есть (документами, похожими на твой JSON). Для обучения тоже хороший вариант, но раз у тебя уже нормализованная структура (категории → товары), реляционная БД выглядит естественнее.

## Авторизация

8. **NextAuth.js (Auth.js)**
Именно то, что тебе нужно по ТЗ: почта, телефон (через кастомный provider или email-magic-link), Google/Facebook OAuth "из коробки". Плюс легко подключить восстановление через Telegram позже, написав кастомный provider.

## Заявки / уведомления

9. **Telegram Bot API**
В ТЗ написано, что заявки могут попадать в Telegram-бот. Это делается через обычный HTTP-запрос к Telegram Bot API (`sendMessage`) из твоего API-роута при создании заказа — не нужна отдельная библиотека, там простой REST.

## Хранение изображений

10. **Cloudinary или Supabase Storage**
В `menu.json` сейчас `image_url` пустые — когда будешь добавлять фото товаров, удобнее хранить их не в самом проекте, а на внешнем сервисе с CDN. Оба варианта бесплатны для учебных объёмов.

## Админка

11. **Тот же Next.js (роут /admin), защищённый через NextAuth**
Отдельный фреймворк для админки не нужен — просто закрытые страницы с формами CRUD, дергающие те же API Routes.

## Деплой

12. **Vercel (frontend+backend) + Supabase/Railway/Neon (PostgreSQL)**
Оба бесплатны в базовых тарифах, отлично подходят для pet/учебных проектов и легко разворачиваются буквально в пару кликов после пуша в GitHub.


## Итоговый стек одним списком
**Next.js + TypeScript** — фреймворк, роутинг для страницы товара и админки
**Tailwind CSS** — стилизация
**Zustand** — состояние корзины
**Font Awesome** — иконки интерфейса
**Swiper/Embla** — слайдер отзывов
**PostgreSQL + Prisma** — база данных и работа с ней
**NextAuth.js** — авторизация (email/телефон/соцсети)
**Telegram Bot API** — приём заявок
**Cloudinary/Supabase Storage** — хранение изображений товаров
**Vercel + Neon/Supabase** — деплой
