обновлял `#hash` в URL, но не докручивал страницу — известная особенность Next.js App Router при
переходе по якорю в пределах той же страницы (навигация clientside не считает такой переход
"настоящей" навигацией). Исправлено: добавлена `scrollToId()` в `lib/utils.ts`
(`element.scrollIntoView` вручную, `event.preventDefault()` на клике), применена в
`CategoryTabs.tsx` и `Nav.tsx` (последний рефакторен: `href="/"` остаётся на `next/link`,
`href="#slug"` — на ручной прокрутке). `app/layout.tsx` дополнен классом `scroll-smooth`,
`Footer.tsx` — классом `scroll-mt-20`, чтобы Header не перекрывал секции при переходе по якорю.

Проверено вручную в браузере (Chrome DevTools MCP): desktop и мобильная (390×844) раскладки,
скролл-спай подсвечивает нужный таб, клик по табу и по пункту "МЕНЮ" в Header корректно

Правки вёрстки по замечаниям пользователя, перед слиянием пункта 5 плана в `main` (ветка

1. **Заголовок секции прятался под табами.** `CategoryTabs` был `sticky top-20` с `py-4`

## Задача 9

Правка по замечанию пользователя: у `CategoryTabs` не нравилась видимая горизонтальная линия
скроллбара, и хотелось перетаскивать табы мышкой влево/вправо (как свайп на телефоне), а не только
тянуть за сам скроллбар. Ветка `fix/category-tabs-drag-scroll`.

- `app/globals.css` — добавлен утилитарный класс `.scrollbar-hide` (кросс-браузерное скрытие
  нативного скроллбара: `scrollbar-width: none` для Firefox, `-ms-overflow-style: none` для
  Edge/IE, `::-webkit-scrollbar { display: none }` для Chrome/Safari). Это единственное
  разрешённое `.agents/rules/code-style.md` исключение из правила "только Tailwind-классы" — самого
  класса для скрытия скроллбара в Tailwind нет.
- `components/catalog/CategoryTabs.tsx` — добавлены обработчики `onMouseDown/onMouseMove/onMouseUp/
  onMouseLeave` на контейнер табов: во время зажатой кнопки мыши `scrollLeft` двигается вручную на
  дельту курсора. Состояние драга (`isDragging`, стартовые координаты) держится в `useRef`, а не
  `useState` — `mousemove` стреляет на каждый пиксель, лишние ре-рендеры не нужны. Клик по табу
  (навигация к секции через `scrollToId`) подавляется, если в рамках того же нажатия мышь сдвинулась
  больше чем на 5px — иначе перетаскивание "дёргалось" бы клик-прокруткой в момент отпускания кнопки
  под табом. На тач-устройствах ничего не менялось — там нативный скролл свайпом уже работал.

Проверено вручную в браузере (Chrome DevTools MCP): скроллбар под табами визуально исчез,
синтетический drag (`mousedown` → серия `mousemove` → `mouseup`) на контейнере корректно двигает
`scrollLeft`; `npm run lint` и `npx tsc --noEmit` — чисто.

**Изменённые/созданные файлы:**

Правка по запросу пользователя: при переходе с карточки товара (не в первой категории каталога) на

**Причина:** активная категория (`activeSlug`) в `Catalog.tsx` хранилась только в локальном
React-состоянии (`useState`, по умолчанию — первая категория). Браузер при возврате назад
корректно восстанавливает `scrollY` (проверено эмпирически — пиксельная позиция восстанавливается
даже без этой правки), но `Catalog` при этом заново монтируется с состоянием по умолчанию — в
итоге восстановленная прокрутка указывала в контент первой категории вместо той, что была
выбрана до перехода.

- `components/catalog/Catalog.tsx` — активная категория теперь дублируется в `sessionStorage`
  (`catalog-active-category`) при каждом клике по табу и читается один раз сразу после гидратации.

  задача 19). Восстановление из `sessionStorage` — `setState` прямо в теле рендера под гвардом
  `restoredFromSession` (паттерн "adjusting state during render" из доков React, на который ссылается
  текст самой линт-ошибки) — без лишнего кадра с неверным табом.
- Разбирал и отклонил альтернативу через `?category=slug` в URL (`useSearchParams` + shallow
  routing `history.replaceState`) — она чище архитектурно (URL как источник истины для `back`), но

## Задача 35

По замечанию пользователя: на странице «Клиенты» появился горизонтальный скролл всей страницы (не только у таблицы). Систематический дебаг (`superpowers:systematic-debugging`) — root cause не в самой таблице клиентов.

`app/admin/(protected)/layout.tsx` — `<main>` (флекс-элемент, `flex-1` внутри `lg:flex`) не имел `min-w-0`. У флекс-элементов браузерный дефолт `min-width: auto` — элемент не может сжаться уже min-content своих потомков. Таблица клиентов (все 6 колонок `whitespace-nowrap`, ни одна ячейка не переносится) требует ~1180px, а флекс реально выделяет `<main>` только ~1140-1155px (1440px экран минус сайдбар) — вместо того чтобы сжать `<main>` и отдать скролл внутреннему `overflow-x-auto` у таблицы, браузер раздувал саму `<main>`, и скроллилась вся страница. На «Заказах»/«Товарах» та же уязвимость в layout присутствует, но их таблицы чуть уже и пока укладываются в доступную ширину — баг не проявляется визуально, но актуален на более узких экранах.

Фикс — `min-w-0` на `<main>` в общем layout (не в конкретной таблице): стандартное решение для этого класса flexbox-багов, закрывает проблему сразу для всех разделов админки.

Проверено (Chrome DevTools MCP, `document.documentElement.scrollWidth` vs `clientWidth` до/после фикса на `/admin/customers`, 1440×900): до фикса `scrollWidth` 1465 > `clientWidth` 1425 (скролл всей страницы); после — оба 1440, `overflow-x-auto` у таблицы взял скролл на себя (`scrollWidth` 1100 > `clientWidth` 1072 у самого блока таблицы). По замечанию пользователя: в `<select>` админки стрелка визуально прилипала к правому краю поля. Ветка `fix/select-arrow-padding`.

**Первая попытка была неверной** (увеличить `padding-right` у нативного select) — в headless Chrome (Chrome DevTools MCP) на глаз казалось, что стрелка сдвигается вместе с отступом, но пользователь показал скриншот из реального браузера на Windows: стрелка осталась прижатой к краю. Причина — на Windows нативный `<select>` часто рисуется темой ОС, и позиция самой стрелки не зависит от `padding` элемента (сдвигается только текст). Коммит с этой неверной правкой удалён (`git reset --hard` + `git push --force-with-lease` на ветке, PR не был открыт).

Так стрелка рендерится одинаково в любом браузере/ОС, а не зависит от нативной темы. Для select'ов с `disabled` (роль пользователя в таблице, статус заказа) — `peer`/`peer-disabled:opacity-60`, чтобы иконка тоже тускнела вместе с полем.
